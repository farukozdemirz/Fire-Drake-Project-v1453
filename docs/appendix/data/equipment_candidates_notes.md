# Equipment candidates (warrior / priest / mage, level 80) - FDP_kn_online read-only extract

## 0. How ITEM is encoded (verified against data + GameServer code)

* **ReqLevel is 1 for every one of the 85920 ITEM rows** (min=1, max=1). ReqLevelMax ranges 40..131; only 9 rows have ReqLevelMax < 80 (700008000 Redistribution Item(Mlddle Class) (+0) (max 59), 800050000 Mount Scroll (+0) (max 40), 810050000 Super Noah (+0) (max 60), 810051000 Hyper Noah (+0) (max 60), 810055000 Spirit of Specialist (+0) (max 60), 810056000 Spirit of Grandmaster (+0) (max 60), 810060000 Symbol of Gladiator  (+0) (max 50), 810073000 Symbol of Gladiator [5 ea] (+0) (max 50), 810075000 Symbol of Gladiator[10 ea] (+0) (max 50)). Server check `CUser::ItemEquipAvailable` (ItemHandler.cpp) = level >= ReqLevel && level <= ReqLevelMax && Rank/Title && STR/STA/DEX/INT/CHA >= Req*; **it does NOT check Class or Race**. So at level 80 the only real gates are the stat requirements (and client-side class/kind rules). Because ReqLevel carries no information, "level bands" below use ItemClass tier (1 low, 2 middle, 3 high, 4 rebirth/unique-class) and stat requirements.

* **Kind** (GameDefine.h `WEAPON_*`, `GetItemGroup()=Kind/10`): 11=dagger, 21=1H sword, 22=2H sword, 31=1H axe, 32=2H axe, 41=1H club/mace, 42=2H mace/hammer, 51=1H spear, 52=2H spear/polearm, 60=shield, 70=bow, 71=crossbow, 110=staff, 210=warrior armor, 220=rogue armor, 230=mage armor, 240=priest armor, 91=earring, 92=necklace, 93=ring, 94=belt, 95/97/98/255 = consumables/scrolls/upgrade items, 0 = special. Warrior combo skills 1055/2055 (dual wield) require swords/axes/maces/spears in both hands, 1056/2056 (2H) require empty left hand and a sword/axe/mace/spear (MagicInstance::IsAvailable).
* **Slot** (enum ItemSlotType): 0=either hand, 1=right hand, 2=left hand, 3=2H right, 4=2H left, 5=pauldron(chest), 6=pads(legs), 7=helmet, 8=gloves, 9=boots, 10=earring, 11=necklace, 12=ring, 13=shoulder, 14=belt, 15/16/17/20 = inventory-only / bag / misc, 100+ = cospre.
* **Class**: 0 = any; 1 warrior, 2 rogue, 3 mage, 4 priest (GROUP_*). Armor tiers above Chitin use 6/8/10/12 (= GROUP_DEFENSE_WARRIOR / GROUP_ASSASSIN / GROUP_PET_MAGE / GROUP_CURSE_CLERIC in GameDefine.h; numerically equal to the master class codes x06/x08/x10/x12). Server `JobGroupCheck(6..12)` compares with the base class (1..4) and would return false, but JobGroupCheck is only used for consumables (CanUseItem), not for equipping; the client most likely restricts these to master classes (unverified). All weapons/shields/accessories have Class 0 except training items.
* **Race**: 0 = all (78153 rows); 19/20 = special (107 rows); **111-114 = set id** (111 Dragon=warrior, 112 Mythril=rogue, 113 Ron=mage, 114 Trial=priest). Set bonus row = SET_ITEM.SetIndex = Race*10000 + sum(slot bits: helmet 2, pauldron 16, pads 512, gloves 2048, boots 4096) (User.cpp SetUserAbility); full 5-piece = Race*10000+6674. KARUS_BIG=1..ELMORAD_WOMAN=13 race codes are character races, not used on items here.
* **ItemType**: 0 normal base, 1 magic, 2 rare, 3 craft, 4 unique (white upgrade effect), 5 upgrade line (green effect), 6 event, 7 pet, 8 cospre, 11/12 rebirth ("reverse") items (UpgradeHandler.cpp: notice + green effect for 5/11/12). ItemClass = upgrade-scroll tier needed (1 low, 2 middle, 3 high, 4 rebirth; 8 = accessory, matched with ItemExt).
* **Item id / upgrade level**: id = 6-digit family + 3-digit variant. The **last digit is the +N level** inside a block of ten: e.g. Graham 121310000 (+0, dmg 72) -> 121310001 (+1) ... 121310009 (+9, dmg 120) -> 121310010 (+10, dmg 140; the name still says "(+0)"). Higher tens/hundreds (121310020, ...030, ...050, ...060-230) are option variants of the same family (e.g. +18 STR, +100 fire damage, unique roll). Armor: 206001000 Chitin Shell Pauldron AC 149 -> 206001009 AC 197 -> 206001010 AC 217. Upgrade code (UpgradeHandler.cpp): ITEM_UPGRADE.nOriginItem = item id % 100000 (last five digits, so one row serves all families), the result is `old id + nGiveItem` (normally +1), success if rand(10000) <= nGenRate; nReqItem1..8 = scroll/material ids, nReqNoah = coin cost.
