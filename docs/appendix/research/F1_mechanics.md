## Q7 Summon/teleport mechanics - raw
- Official 1.298 server ExecuteType8 (Open-KO MagicProcess.cpp, https://github.com/Open-KO/KnightOnline/blob/master/src/Server/Ebenezer/MagicProcess.cpp): Type-8 "Warp, resurrection, and summon spells". WarpType 1 = send to resurrection/bind point (Gate/Escape-like; party version via region check); 11 = resurrect dead player (HP full, ExpRecover%); 12 = summon target within SAME zone (warp target to caster x,z); 13 = summon target from a DIFFERENT zone (ZoneChange to caster); 20 = random self-teleport within 20 m; 2,3,5,21 not implemented. Fails if target dead (non-res), alive (res), or already warping. Moral check MORAL_PARTY: target must be in caster's party. In ZONE_BATTLE (war zone), a warp spell on a player who regened <180 s ago (CLAN_SUMMON_TIME=180) fails.
- turkmmo 2012 mage list: "Summon party members" basic skill (S.P 4); Gate 15 (to town, HP irrelevant); Escape 30 (party to town). Kalais other.php: ESC "not working in PvP areas"; "TP/666666 = summon me please".
- Resurrection: priest res consumes Stones of Life from the DEAD target (Open-KO: `pTUser->ItemCountChange(UseItem, 1, NeedStone)` for type-5 sub-type 3), not allowed if target level <=5. Kalais: 30-stone res = 80% exp back; 4-stone = 60%. turkmmo priest list: Loved Resurrection 33 (60%), Blessed Resurrection 42 (70%), 54 (80%).

## Client auto-attack (R) timing - official client logic as published in Open-KO (src/Client/WarFare/PlayerMySelf.cpp, GameProcMain.cpp) [OLDER-1.298; Korean comments = original code]
- Melee auto-attack interval = weapon siAttackInterval/100 s (comment: "100 = 1 s, 110 = 1.1 s") × item-ext interval %, divided by m_fAttackDelta (attack-speed buffs e.g. Outrage 120%, Frenzy 130%, Berserk Echo 140%; Slow debuff 70%).
- "cannot auto-attack while casting": auto-attack blocked while IsCasting() (spell state, stun, or m_fDelay>0; m_fDelay=0.3 s after an instant skill is sent).
- MsgSend_Attack sends the TABLE interval + 0.1 s ("공격 주기를 같이 줘서 해킹을 막는다" = send attack period to prevent hacking) and distance×10; server compares that number with item Delay => the check validates the client's claimed interval, not the real elapsed time.
- Skills have independent per-skill recast (iReCastTime/10 s) and cast time iCastTime/10 × attack delta; many warrior hits have 0.5 s recast, so alternating R and skills fills the gaps (= "combo").
